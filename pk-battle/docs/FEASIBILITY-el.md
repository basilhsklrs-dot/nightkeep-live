# PK Auto Accept: μελέτη σκοπιμότητας και τι υλοποιήθηκε

Ημερομηνία: 2026-10-25. Η κατάσταση κάθε σημείου χαρακτηρίζεται με έναν από τους εξής όρους: **ΕΠΑΛΗΘΕΥΜΕΝΟ** (δοκιμάστηκε εδώ), **ΥΛΟΠΟΙΗΜΕΝΟ – ΑΔΟΚΙΜΑΣΤΟ ΣΕ ΣΥΣΚΕΥΗ** ή **ΜΗ ΔΙΑΘΕΣΙΜΟ**.

## 1. Επίσημο API ή SDK (Option A): ΜΗ ΔΙΑΘΕΣΙΜΟ

- Το TikTok δεν προσφέρει δημόσιο API ή SDK που να αποδέχεται προσκλήσεις PK/Match για λογαριασμό δημιουργού. Δεν βρέθηκε επίσημη τεκμηρίωση. Όλα τα σχετικά εργαλεία είναι ανεπίσημα και μόνο διαβάζουν δεδομένα (tiktok-live-connector/EulerStream, TikTokLive, tik.tools).
- Το `tiktok-live-connector` 2.5.0, που χρησιμοποιεί ήδη το NIGHTKEEP μέσω EulerStream, **μόνο διαβάζει** μηνύματα `WebcastLinkMicBattle`, `WebcastLinkMicArmies` και `WebcastLinkMicBattlePunishFinish`. Δεν έχει καμία μέθοδο αποδοχής πρόσκλησης. Αυτό το επιβεβαίωσα από τους τύπους της βιβλιοθήκης.
- Το μήνυμα `LinkMicBattle` περιέχει `action = INVITE(1) / ACCEPT(7) / OPEN(4) / FINISH(5)`, `anchorsInfo` (τα στοιχεία του αντιπάλου) και `battleSettings.duration`. Το `LinkMicArmies` περιέχει το **επίσημο PK score ανά δημιουργό** και τους top supporters. Ο server τα αξιοποιεί αποκλειστικά για ανάγνωση.
- Δεν είναι επαληθευμένο αν το `INVITE` φτάνει στο δημόσιο stream του δωματίου. Οι προσκλήσεις συνήθως πηγαίνουν μόνο στην εφαρμογή του δημιουργού. Γι' αυτό η ανίχνευση της πρόσκλησης γίνεται στο tablet και ο server απλώς επιβεβαιώνει την έναρξη του PK.

## 2. Android AccessibilityService (Option B): ΥΛΟΠΟΙΗΜΕΝΟ – ΑΔΟΚΙΜΑΣΤΟ ΣΕ ΣΥΣΚΕΥΗ

Βρίσκεται στο `pk-battle/android/.../PkAutoAcceptService.kt` και τη λογική αναγνώρισης στο `PkMatcher.kt`.

| Απαίτηση | Πώς καλύπτεται |
|---|---|
| Ρητή ενεργοποίηση από τον χρήστη | Ενεργοποιείται μόνο από Ρυθμίσεις → Προσβασιμότητα. Η προεπιλεγμένη λειτουργία είναι **OFF** |
| Άμεση απενεργοποίηση | Διακόπτης OFF/ASSIST/AUTO στην εφαρμογή και πλακίδιο Quick Settings «PK Accept» |
| Όχι root, κρυφά/ιδιωτικά APIs ή παράκαμψη ασφάλειας | Χρησιμοποιεί μόνο το δημόσιο AccessibilityService API. Έχει `canPerformGestures=false`, άρα **δεν μπορεί καν** να κάνει κλικ σε συντεταγμένες |
| Αναγνώριση στοιχείων αντί για συντεταγμένες | Κάνει μόνο `ACTION_CLICK` στο ίδιο το κουμπί Accept ή στον πλησιέστερο clickable γονέα του |
| Έλεγχος κατάστασης εφαρμογής | Λειτουργεί μόνο σε παράθυρα TikTok. Πρέπει να βρει **στο ίδιο dialog** κείμενο πρόσκλησης, κουμπί Accept **και** κουμπί Decline. Αλλιώς δεν κάνει τίποτα |
| Έλεγχος αποστολέα | Προαιρετική λίστα επιτρεπόμενων αποστολέων (allowlist) |
| Αποφυγή διπλών αποδοχών | Υπογραφή dialog με διάστημα 60 s, ρυθμιζόμενο cooldown και όριο αποδοχών ανά ώρα |
| Ασφαλής διακοπή σε άγνωστο UI | Σταματά αν υπάρχουν πολλά κουμπιά Accept, αν το Accept δεν είναι clickable/ενεργό ή αν ο στόχος περιέχει και το Decline |
| Επιβεβαίωση | Ελέγχει ξανά μετά από 2,5 s ότι το dialog έκλεισε. Ο server επιβεβαιώνει με `pk_started` από το TikTok (μετρητής `verifiedAccepts`) |
| Assisted fallback | Η λειτουργία **ASSIST** ειδοποιεί και δονεί τη συσκευή, και πατάς εσύ το Accept |
| Βαθμονόμηση | Το «CAPTURE TIKTOK UI» καταγράφει το πραγματικό δέντρο στοιχείων του TikTok. Μπορείς να προσθέσεις φράσεις, ετικέτες ή view IDs χωρίς νέο build |

Αυτοματοποιημένοι έλεγχοι που πέρασαν: 9/9 JVM unit tests για τον matcher (αγγλικά, ελληνικά με τόνους, allowlist, ασαφή κουμπιά, αποκλεισμός λάθος στόχου, view IDs).

**Τι ΔΕΝ έχει ελεγχθεί:** Δεν έχει γίνει ακόμα πραγματική πρόσκληση στο Xiaomi Pad 5. Οι ακριβείς λέξεις και η δομή του dialog της τρέχουσας έκδοσης TikTok είναι άγνωστες μέχρι να γίνει capture. Μέχρι τότε το Auto Accept **δεν** θεωρείται ολοκληρωμένο.

### Κίνδυνοι πολιτικής TikTok (σημαντικό)

- Οι Όροι Χρήσης του TikTok απαγορεύουν γενικά την αυτοματοποιημένη πρόσβαση και τη χρήση μη εξουσιοδοτημένων εργαλείων τρίτων. Η αυτόματη αποδοχή πρόσκλησης μέσω accessibility μπορεί να θεωρηθεί αυτοματοποίηση και να οδηγήσει σε περιορισμούς στον λογαριασμό. Τον κίνδυνο τον αναλαμβάνει ο κάτοχος του λογαριασμού.
- Η λειτουργία **ASSIST** (ειδοποίηση και χειροκίνητη αποδοχή) αποφεύγει αυτόν τον κίνδυνο. Προτείνω να ξεκινήσεις με ASSIST και να δοκιμάσεις AUTO μόνο με αντίπαλο που εμπιστεύεσαι.
- Το MIUI στο Xiaomi μπορεί να «σκοτώνει» υπηρεσίες στο παρασκήνιο. Χρειάζεται «No restrictions» στη μπαταρία και Autostart (δες INSTALL-el.md).

## 3. Πώς φτάνει το παιχνίδι στο LIVE (Option C): ΧΡΕΙΑΖΕΤΑΙ ΔΟΚΙΜΗ

| Τρόπος | Αναμενόμενη συμπεριφορά | Κατάσταση |
|---|---|---|
| TikTok LIVE «Mobile gaming» (κοινή χρήση οθόνης) και η εφαρμογή NIGHTKEEP PK σε πρώτο πλάνο | Οι θεατές βλέπουν το παιχνίδι. Το AccessibilityService βλέπει και αναδυόμενα παράθυρα του TikTok (`flagRetrieveInteractiveWindows`) | Αδοκίμαστο: δεν είναι γνωστό αν το TikTok επιτρέπει PK σε gaming LIVE στον λογαριασμό σου |
| Split-screen: TikTok camera LIVE + παιχνίδι | Τα Android 11+ (multi-resume) κρατούν και τα δύο ενεργά | Αδοκίμαστο |
| Κανονικό camera LIVE + παιχνίδι σε δεύτερη συσκευή ή οθόνη | Το παιχνίδι λειτουργεί ως πίνακας. Οι θεατές το βλέπουν μόνο αν είναι μέσα στο κάδρο | Λειτουργεί με βεβαιότητα, όχι όμως ως overlay |
| TikTok LIVE Studio (PC) με browser source την ίδια URL | Η συνηθισμένη λύση overlay | Εκτός tablet |

Το παιχνίδι **δεν** παρουσιάζεται ποτέ ως πραγματικό PK όταν δεν είναι. Όταν τρέχει με προσομοιωμένα events εμφανίζει σήμα **SIMULATION**, και το «GAME SCORE» διακρίνεται πάντα από το «TIKTOK PK SCORE».

## 4. Ποιος θεατής ανήκει σε ποια ομάδα

- **LEFT**: τα events από το δικό σου δωμάτιο (σύνδεση στο @nightkeep.live).
- **RIGHT**: μόλις αναγνωριστεί ο αντίπαλος από το `anchorsInfo`, ο server ανοίγει **δεύτερη σύνδεση στο δωμάτιο του αντιπάλου**, και τα events από εκεί πάνε στο RIGHT. Αυτό απαιτεί EulerStream sign quota για δεύτερο δωμάτιο.
- **Fallback (τεκμηριωμένο)**: αν αποτύχει η σύνδεση στο δωμάτιο του αντιπάλου, η **αύξηση του επίσημου PK score** του αντιπάλου (που είναι η αξία των δώρων του κοινού του) μετατρέπεται σε δράσεις για την ομάδα RIGHT με όνομα «<αντίπαλος> fans». Δεν υπάρχει διπλομέτρηση, γιατί όταν η σύνδεση στο δωμάτιο του αντιπάλου είναι ενεργή το fallback απενεργοποιείται. Η διάγνωση δείχνει ποιος τρόπος χρησιμοποιείται (`rightAttribution`).
- Κανένας θεατής δεν ανατίθεται σε ομάδα «στην τύχη».
